# AI-SDLC v0.9.8 Release Notes

## Positioning

`0.9.8` makes the next work item on mainline trustworthy again. It carries the
merged WI219 behavior into the published CLI: linked work-item identity is used
consistently, mainline truth remains reliable through squash merges, and new
specifications ask for value and delivery boundaries before implementation.

## What Changed

### 1. Current work-item guidance follows the linked work item

- Status, readiness, execute authorization, and resume guidance use the same
  linked-first work-item identity and specification directory.
- If a linked work item is missing or invalid, the affected surfaces report it
  as unavailable instead of silently reading an older work item.
- Existing checkpoints without a linked work item retain their previous
  behavior.

### 2. Mainline truth handles real merge history more accurately

- Truth checks use an existing remote default branch when the local default is
  strictly behind it, without fetching or moving refs.
- Formal control-only changes are no longer treated as product execution, while
  code, tests, configuration, scripts, and product-document changes still
  count as execution evidence.
- Recorded implementation evidence remains attributable after a squash merge,
  so close and merge guidance reflects the merged revision.

### 3. New specifications make value and scope explicit

- Both standard and direct-formal spec templates now ask for observable user
  value or reproducible risk, current evidence, the minimal and alternative
  approaches, total delivery cost, scope, exit conditions, and a decision.
- A small or inapplicable change may use `not-applicable`; the guidance does
  not add a scoring system, a new CLI command, persistent state, or blockers
  for existing specifications.

## Compatibility Notes

- Existing specifications do not need backfilling.
- Checkpoint schema, status JSON shape, commands, and lifecycle states are
  unchanged.
- The Vue3 v1.8 `public-primevue` defaults and explicit `vue2` /
  `enterprise-vue2` compatibility remain unchanged.
- `ai-sdlc init .` remains the ordinary setup entry; `adapter status` and
  `run --dry-run` remain troubleshooting commands.

## Install And Upgrade

Use the platform release asset from
`https://github.com/sinclairpan-git/Ai_AutoSDLC/releases/download/v0.9.8`.

- Windows: download `ai-sdlc-offline-0.9.8-windows-amd64.zip`, then run
  `install_offline.ps1 -AddToPath` for a new install or
  `install_offline.ps1 -UpgradeExisting` to replace an older CLI.
- macOS / Linux: download the matching `.tar.gz` asset, unpack it, then run
  `install_offline.sh --add-to-path` for a new install or
  `--upgrade-existing` to replace an older CLI.
- Existing users can run `ai-sdlc self-update install --version 0.9.8` after
  release assets are published. Run `ai-sdlc self-update check` first if
  desired; if an older CLI reports `No such command 'install'`, use the
  matching platform package and its upgrade path.
- `python -m ai_sdlc ...` remains the fallback when the shell has not refreshed
  PATH.

## Verification Before Publish

- `uv run pytest tests/unit/test_verify_constraints.py tests/integration/test_github_workflows.py tests/integration/test_offline_bundle_scripts.py -q`
- Focused WI219 regression tests, `uv run ruff check` on changed Python, and
  `uv run ai-sdlc verify constraints`
- `git diff --check`, exact-HEAD review, and required pull-request checks
- `release-build.yml` produces smoke-passed Windows, macOS, and Linux assets;
  `release-artifact-smoke.yml` then verifies the published assets
