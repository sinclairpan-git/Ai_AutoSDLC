# AI-SDLC v0.9.9 Release Notes

## Positioning

`0.9.9` turns the work delivered across 18 mainline carriers into a safer,
more direct release experience: teams can begin from one ordinary-user entry,
keep a work item's context intact, and receive platform assets whose source and
installation path are independently verifiable.

## What Users Get

### One clear path from a project to the next useful action

- `ai-sdlc init .` remains the normal starting point for a new or existing
  project. It gives a result and one next action instead of requiring setup
  archaeology or a manual diagnostics sequence.
- The active linked work item stays consistent across status, readiness,
  authorization, and resume guidance. A missing or invalid link is reported
  plainly rather than silently falling back to unrelated work.
- Continuity artifacts keep the current goal, evidence, and next step close to
  the work item, making interrupted work easier to resume without recreating
  context.

### Release assets that are easier to trust and recover with

- Windows, macOS, and Linux offline packages carry the runtime they need and
  keep the same install and upgrade commands across the release notes and user
  guide.
- The user-guide paths cover fresh and existing projects, including a direct
  Windows shim when the current terminal has not refreshed PATH yet.
- Release downloads are checked against their build provenance before install;
  the published-asset smoke path validates the assets users actually download,
  not only a local source-tree build.

### A release boundary tied to the work that belongs in it

- The release candidate is evaluated from the declared work-item dependency
  closure, so unrelated historical program debt does not masquerade as a
  release failure.
- The same readiness audit protects pull requests and the exact-tag build
  before assets, attestations, or uploads run.
- Existing global Program Truth remains honest about unrelated blockers while
  the candidate audit explains the actionable scope for this release.

## Compatibility Notes

- Existing specifications, checkpoints, commands, status JSON, and lifecycle
  states remain compatible.
- The Vue3 v1.8 `public-primevue` defaults and explicit `vue2` /
  `enterprise-vue2` compatibility remain unchanged.
- `adapter status` and `run --dry-run` remain troubleshooting commands, while
  `ai-sdlc init .` remains the ordinary setup entry.

## Install And Upgrade

Use the platform release asset from
`https://github.com/sinclairpan-git/Ai_AutoSDLC/releases/download/v0.9.9`.

- Windows: download `ai-sdlc-offline-0.9.9-windows-amd64.zip`, then run
  `install_offline.ps1 -AddToPath` for a new install or
  `install_offline.ps1 -UpgradeExisting` to replace an older CLI.
- macOS / Linux: download the matching `.tar.gz` asset, unpack it, then run
  `install_offline.sh --add-to-path` for a new install or
  `--upgrade-existing` to replace an older CLI.
- Existing users can run `ai-sdlc self-update check`, then
  `ai-sdlc self-update install --version 0.9.9`. If an older CLI reports
  `No such command 'install'`, use the matching platform package and its
  upgrade path.
- `python -m ai_sdlc ...` remains the fallback when the shell has not refreshed
  PATH.

## Verification Before Publish

- `release-build.yml` checks the exact tag, candidate readiness, and each
  platform package before producing or uploading assets.
- `release-artifact-smoke.yml` downloads the published Windows `.zip` and
  macOS / Linux `.tar.gz` assets and verifies their installation path.
- The release also requires focused regression tests, constraints verification,
  exact-HEAD review, and required pull-request checks.
